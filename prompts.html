Phase 0 — Ground Rules & Guardrails

Standing instructions were defined prior to prototype development to maintain technical rigor:

  • No guessing bug causes: Before writing any fix, categorize as proven from code/logs, provable in seconds, or an open hypothesis.
  • Exhaustive source integrity: Never omit a data source; if an external API or dataset is unavailable, explicitly document it.
  • Plain language without dumbing down: Strip financial jargon while preserving all mathematical and regulatory depth.

Key Steering Decisions: Accepted vs. Overruled

AI Proposal / Pushback Product Decision Rationale
Delete the "sell next week" stock comparison. Overruled (Kept): Demoted rather than deleted. It is the only real data point that disproves the misconception that "charges are just a tiny % of my gains".
Label projections as "expected gains". Accepted: Changed to "past trailing returns". Fintech ethics & compliance: a projection is an unsubstantiated forward-looking claim.
Build a hardcoded static fee lookup table. Accepted: Replaced with deterministic test-backed formulas. Lookup tables rot quickly; algorithmic functions backed by 23 assertions are verifiable over time.
